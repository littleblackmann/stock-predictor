# 2026-10-06 · v1.7.3 啟動、分析與更新的資源負擔

使用者回報開啟與更新軟體會讓整台電腦、滑鼠及其他程式變慢，並要求直接改善軟體，不以硬體配備或版本作為處理前提。

## 已確認的軟體問題

- v1.7.2 在開啟主視窗前載入 prediction_worker，間接載入 NumPy、pandas、yfinance 及 OpenAI SDK；PredictionLogger 也在模組頂層載入 yfinance。尚未分析股票就付出匯入成本。
- 啟動後 2／3／5 秒分別排入回填、股票清單更新、訊號掃描與版本檢查，使用未限制的全域執行緒池。正式短線模型原本 n_jobs=2；不能把未使用的舊 Transformer／n_jobs=-1 路徑當成現行問題。
- 更新每 64 KiB 發送進度，快速下載可產生密集 GUI 事件。先 testzip 全包解壓檢查 CRC，再 extractall 解壓一次，造成重複工作。

## 修改

- 分析、行情及新聞套件延至工作器需要時載入；沒有新聞分析需求時不載入 OpenAI SDK。預測紀錄視窗也延後載入。
- 主視窗使用 maxThreadCount=1 的專用池，手動回填共用此池。維護工作延後到啟動後 20–30 秒，分析／更新或其他工作進行中則延後。實際預測會先更新交易日曆，保留交易日／收盤資料正確性。
- 程式自身設定數值函式庫執行緒上限 1，LightGBM 使用 n_jobs=1；保留資料、特徵、期間、種子、校準與驗證規則。這是負擔改善，沒有新實盤命中率證據。
- Windows 工作器暫時使用 THREAD_MODE_BACKGROUND_BEGIN 降低 CPU／I/O 排程優先權，在 finally 還原；僅此程式／執行緒，不修改全域系統設定。
- 更新進度最多約 10 次／秒，保留起始、重置與完成通知。下載限制 8 MiB/s；解壓限制 16 MiB/s，64 KiB 分批處理且以 sleep 讓出資源。
- 解壓前仍檢查所有路徑與連結；ZipExtFile 讀到 EOF 時核對 CRC，避免重複解壓。SHA-256、檔案大小、TLS、版本、磁碟空間及續傳檢查保留。CRC 錯誤不會啟動安裝。
- 安裝 helper 使用 BelowNormal 程序優先權，重新開啟應用時恢復 Normal。完整更新包沿用 AppData 個人資料。

## 驗證與發布

- 原有 42 項與新增 7 項 unittest 共 49 項通過；涵蓋啟動模組沒有分析套件、進度節流、限速、失敗時優先權還原、CRC／不啟動損毀包、維護工作延後。
- EXE、封裝、量測與公開 Release 證據詳見下方各節。尚未操作媽媽的電腦；不能承諾任何機器上都完全不卡。
- 舊版更新到本版的那一次仍執行舊版更新器；新更新負擔控制在成功升級後生效。舊版若更新時仍卡，可關閉軟體後用瀏覽器下載完整 ZIP 到新資料夾。
