# Day 15 — 2026-04-20

## 主題：v1.5.4 CSV schema 錯位緊急修復（v1.5.5）

> 使用者回報：v1.5.4 上線後，父母電腦 UI「預測記錄」沒看到新增的「原始模型機率」欄位，
> 且 4/20 的預測記錄看起來欄位錯位（「3日走勢」顯示 0.5327、「實際」顯示 3日走勢文字）。

---

## 根因分析

v1.5.4 的改動範圍檢查：

| 檔案 | Day 14 有無修改 | 狀態 |
|------|----------------|------|
| `data/prediction_logger.py`（FIELDS 10 欄） | ✅ 修改 | 新增 raw_up_prob |
| `ui/prediction_log_dialog.py`（UI COLUMNS） | ❌ 漏改 | 仍只有 8 欄 |
| CSV header migration | ❌ 沒做 | 造成欄位錯位 |

### Bug 1：UI 漏加「原始機率」欄位
`prediction_log_dialog.py` 的 `COLUMNS` 列表沒有同步加入 `raw_up_prob`，
所以即使 CSV 有這個欄位值，UI 也看不到。

### Bug 2：舊 CSV header 未升級，新記錄欄位錯位（更嚴重）
- 舊 CSV header 只有 9 欄（無 raw_up_prob）
- `append()` 是 append 模式，`if not file_exists: writer.writeheader()` 只在新檔才寫 header
- v1.5.4 的 `DictWriter` 按 10 欄 `FIELDS` 順序寫入新記錄
- `DictReader` 讀取時依舊 9 欄 header 解析 → 全部錯位一格

錯位對照：
| CSV 位置 | 舊 header | v1.5.4 寫入的實際值 |
|---------|-----------|---------------------|
| 第 6 欄 | gpt_3day | raw_up_prob（"0.5327"） |
| 第 7 欄 | actual | gpt_3day（"明日:偏多(中)..."） |
| 第 8 欄 | actual_return | actual |
| 第 9 欄 | correct | actual_return |
| 第 10 欄 | （無） | correct → 被 DictReader 丟掉 |

這完全符合使用者截圖上 4/20 記錄的異常表現。

## 完成項目

### 1. UI 新增「原始機率」欄位

`ui/prediction_log_dialog.py`：
- `COLUMNS` 在「上漲機率」和「3日走勢」之間插入 `raw_up_prob`
- `_load_table()` 顯示 `raw_up_prob`，舊記錄（空值）顯示「—」
- 自動延伸欄改用 `gpt_3day` 名稱查詢索引，避免欄位重排時寫死 index 失準

### 2. CSV header 自動 migration

`data/prediction_logger.py` 新增 `migrate_header_if_needed()`：
- 偵測第一行 header 有無 `raw_up_prob`
- 若缺，讀入全部 raw rows，依欄位數分流：
  - 9 欄記錄：補空 `raw_up_prob`（舊資料沒這值）
  - 10 欄記錄：依新 FIELDS 順序重對齊
- 重寫成新 10 欄 header
- `append()` 與 `load_all()` 都在開頭呼叫，雙保險
- 第二次呼叫為 no-op（只讀第一行檢查 header）

### 3. Smoke test

本機 35 筆舊記錄 + 模擬 2 筆錯位記錄測試通過：
- 舊 9 欄 header → 10 欄新 header
- 舊記錄 actual/actual_return/correct 全部保留在正確欄位
- 錯位記錄正確重對齊（raw_up_prob=0.5327, gpt_3day=走勢文字, actual=空）
- 第二次 migration 回傳 0

## 晚間討論：目前準確率評估 & 「能否從歷史記錄直接學規律」

> 使用者問：「目前準確率到底準不準？」、「可不可以直接拿以前多筆紀錄判斷規律？」

### 目前準確率估計（討論共識）

| 情況 | 預期準確率 |
|------|-----------|
| 整體平均 | 51–54% |
| 高信心度（up_prob > 0.60 或 < 0.40） | 55–60% |
| 臨界區（0.45–0.55） | ~50%（等同丟硬幣） |

理由：
- 日線二元預測的理論天花板 52–58%（業界共識）
- v1.5.4 的降情緒 + `is_unbalance` 是「修極端」不「加平均」：Day 14 那種 89% 空頭行情能拉上來，但正常盤整/多頭期反而可能略降
- v1.5.5 沒動預測邏輯，準確率 = v1.5.4

### 為什麼不能直接從 35 筆記錄學規律（重要盲點）

使用者的直覺合理，但有四個結構性問題：

1. **LightGBM 本來就在做這件事**：模型 training set 是 2500 天 × N 股票 ≈ 20,000+ 筆。再加 35 筆是 0.17% 增量，對模型來說是 noise level
2. **CSV 記錄的是「結果」不是「特徵」**：`prediction_log.csv` 只有 `up_prob + actual`，**沒記**當時吃進去的 32~45 維 raw features 和 SHAP top 5。少了結構化特徵，任何 meta-learning 都做不起來
3. **規律隨 market regime 改變**：空頭期學到的「模型 up 命中率 11% → 反著用」，在下次多頭期會慘賠。非平穩性是金融預測的根本問題
4. **統計意義不夠**：35 筆樣本的 95% CI 約 ±17%，任何「規律」都可能是運氣

### 待辦清單（2026-04-21 開工）

依 ROI 排序，全部**不需改模型**：

1. **信心度分層命中率統計（最高 ROI，~30 分鐘可做）**
   - 按 up_prob 分層：`>0.60 / 0.55–0.60 / 0.45–0.55 / 0.40–0.45 / <0.40`
   - 看是否呈 U 型分佈（兩端 >55%、中間 ~50%）→ 模型自信度有意義，可信高信心度
   - 若是平的（都 ~50%）→ up_prob 數字本身不帶資訊，模型只會丟硬幣
   - UI 可放在 `預測記錄` 視窗或 `趨勢圖` 對話框新增分頁

2. **補 SHAP top 5 記錄到 CSV**（為 meta-learning 鋪路）
   - `FIELDS` 加 `shap_top5` 欄位（格式：`特徵名:值|特徵名:值|...`）
   - `append()` 從 `result["shap"]` 取 top 5
   - **記得寫 migration**：承襲 v1.5.5 的 `migrate_header_if_needed()` 擴充邏輯（參考 memory 的 `feedback_csv_schema_migration`）
   - 累積 200+ 筆後才有資格做 meta-learning

3. **純模型 vs 加情緒 A/B 分析**（raw_up_prob 的原本用途）
   - 等 `raw_up_prob` 累積 20 筆以上 actual 回填
   - 比較 `raw_up_prob > 0.5` 命中率 vs `up_prob > 0.5` 命中率
   - 若加情緒後變差，直接把 `SENTIMENT_WEIGHT` 砍到 0%

4. **Symbol-specific 命中率可視化**
   - `get_stats()` 已有 `by_symbol`，但沒畫圖
   - 可能發現某些標的長期 <40% → 不推薦給父母跟單
   - 趨勢圖對話框可新增分頁

5. **預測 vs 市場 baseline 常駐報表**
   - 期間市場漲幅比例 X% vs 模型預測 up 比例 Y%
   - Y ≈ X → 模型只是跟隨市場（沒 edge）
   - 穩定偏離且命中率 >50% → 真有 alpha
   - Day 14 做過一次性分析，但該變常駐

### 暫緩 / 後續才做

- **Meta-learning（DEVLOG Day 14 待開發功能清單的第 2 條）**：要先等第 2 項補 SHAP 記錄 + 累積 200+ 筆 + 跨 2~3 個月 market regime，急不得
- **把預測目標從「日線方向」改成「3 日累積報酬 > 1%」**：拉長週期能把天花板從 52~58% 拉到 60%+，但要動訓練標籤、所有模型重訓，工程量大
