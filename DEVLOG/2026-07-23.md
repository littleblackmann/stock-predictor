---

## 為什麼選「保留 openai 套件 + 換 base_url」

OpenRouter 提供的是 **OpenAI 相容端點**，所以有兩種做法：

| 做法 | 影響範圍 | 風險 |
|------|---------|------|
| 改用 `requests` 手刻 HTTP | 要重寫全部 4 處呼叫 + 錯誤處理 + 重試 | 高 |
| **保留 `openai` 套件，只改 `base_url`** | 只動 client 建構那一段 | **低（採用）** |

第二種還有個關鍵好處：**PyInstaller 打包設定完全不用動**。
`.spec` 的 `hidden_imports` 沒列 `openai`（靠直接 import 偵測），
換套件的話要重新驗證打包，等於再賭一次 Day 5 那種打包地獄。

## 完成項目

### 1. `data/config_manager.py` — 設定中樞

- 新增 `OPENROUTER_BASE_URL = "https://openrouter.ai/api/v1"`
- 新增 `OPENROUTER_APP_URL` / `OPENROUTER_APP_NAME`（OpenRouter 排行榜來源標示，選填）
- 設定鍵 `openai_api_key` / `openai_model` → `openrouter_api_key` / `openrouter_model`
- `AVAILABLE_MODELS` 從 6 個純 GPT 字串，改為 10 個 tuple：
  `(模型 ID, 顯示名稱, 分組, 說明含參考費用)`
- 新增 `_migrate_legacy_keys()` 自動遷移舊設定

### 2. 舊設定遷移邏輯（重要）

```
舊 key sk-proj-...  → 丟棄（OpenAI key 在 OpenRouter 無效），要求重填
舊 key sk-or-...    → 沿用（本來就是 OpenRouter key）
舊 model gpt-4o     → 補前綴變 openai/gpt-4o，不在 10 大清單 → 退回預設
舊 model 空值        → 預設 openai/gpt-5.4-mini
最後 pop 掉舊鍵，避免兩套設定並存
```

實測三種情境輸出正確。

### 3. `data/news_sentiment.py` — API 呼叫

- `OpenAI(api_key=...)` → `OpenAI(api_key=..., base_url=OPENROUTER_BASE_URL, default_headers={...})`
- `max_completion_tokens` → `max_tokens`（OpenRouter 相容參數名）
- 讀取新設定鍵，模型預設值改為 `DEFAULT_MODEL`
- 訊息文字 `OpenAI 未啟用` / `GPT 未啟用` → `OpenRouter 未啟用` / `AI 未啟用`

### 4. `ui/settings_dialog.py` — 模型選單

- API Key 欄位標題、placeholder 改為 `sk-or-v1-...`，加上申請網址提示
- 下拉選單改為**迴圈讀取 `AVAILABLE_MODELS`**，不再寫死兩組 GPT 字串
  → 之後要加減模型只改 `config_manager.py` 一處
- 依廠商自動分組（分組標題 `setEnabled(False)` 不可選，組間插分隔線）
- 每個項目掛 ToolTip（模型 ID + 說明）
- 新增 `_on_model_changed()`：選到哪個模型就在下方顯示該模型的說明與參考費用
- 訊號連接放在 label 建立**之後**，避免初始化期間觸發抓不到 widget

### 5. 順手修的既有 bug

`_analyze_no_news()` 原本 `max_completion_tokens=150`。
推理型模型（GPT-5.x、Claude Opus）會先耗 token 思考，150 全被吃掉 → `content` 回傳空字串 → JSON 解析失敗。
**這在原本的 gpt-5.4-mini 上就已經是隱性 bug 了**，不是換 OpenRouter 才有。改為 512。

## ⚠ 為什麼這版先不發 GitHub Release

自動更新是全自動的（下載→覆蓋→重啟）。
如果現在發 v1.6.0 Release，**父母的電腦會自動更新，然後新聞情緒功能直接停擺** ——
因為舊的 OpenAI key 會被遷移邏輯丟棄，而他們不會自己去申請 OpenRouter key。

正確順序：
1. 本機申請 OpenRouter key → 填進設定 → 實測預測流程正常
2. 確認沒問題後，**先幫父母的電腦設定好新 key**（或在更新對話框講清楚）
3. 才發 Release

所以本次只做 commit & push，`version.json` 已標 1.6.0 但沒有對應 tag，
updater 比對不到 Release 就不會觸發更新，是安全的。

## 教訓

換 API 供應商時，**設定鍵改名一定要配遷移邏輯**，而且要想清楚舊值能不能沿用。
這次舊的 API Key 是不能沿用的（不同家的 key），如果無腦搬過去，
使用者會看到「key 有填但一直失敗」，比直接清空還難debug。

跟 Day 15 的 CSV schema 教訓是同一類問題：
**資料格式一改，就要問「舊資料怎麼辦」**。
